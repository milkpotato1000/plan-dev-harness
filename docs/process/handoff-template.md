# Handoff 내용 양식

이 문서를 복사해 역할 소유 경로에 작성·커밋한 뒤 workflow_control.py handoff로 연결한다.

- 주제와 사용자에게 필요한 이유:
- 실제 완료 결과:
- 검증한 범위와 증거:
- 실패/미확인/남은 결정:
- 받는 역할과 다음 행동:
- 관련 P카드와 계약:
- 정확한 전체 커밋 SHA와 커밋된 문서 경로:
- 중지/재개 권한과 현재 상태:
- 인간 전달 지시/기존 위임의 출처·범위·유효성:
- 확인한 수신 프로젝트·역할·채팅 참조(비공개 값은 공개 문서에서 별칭 사용):
- 실제 발송 시도/결과 참조 또는 파일 인계·미발송 이유:
- 실제 수신 응답 관찰 근거 및 마지막 확인 상태:

전달 기록의 PENDING/SENT/ACKNOWLEDGED는 도구 결과와 수신 증거로만 갱신한다.
대화 전체나 인증정보를 복사하지 않는다. 메시지는 새 권한/계약 승인을 만들지 않는다.
발송 전 커밋이 필요한 문서에는 당시 확인된 사실만 적는다. 이후 전달/수신 결과는
연결된 근거 문서에 추가·커밋한다. event가 가리키는 원본 커밋을 바꿔 같은 인계를 재생성하지 않는다.

Plan은 실제 SENT를 커밋·push한 뒤 ACK/채택/완료 대기 없이 응답을 종료한다.
미관찰 ACK는 다음 자연스러운 조회까지 SENT로 유지한다. busy dev는 현재 P를 보존하고
안전한 경계 뒤 정확 채택한다. 이 문서는 구현 완료나 중지 재개를 의미하지 않는다.

사용자 검토/결정 인계는 공통 request key·P/criterion·질문 종류/범위·artifact commit/version/hash·
기존 실제 사용자 답변 출처를 포함한다. Plan은 같은 대기/답변 질문을 재발행하지 않고 실제
파일/뷰를 검토한다. user-review-template.md 참조. 역방향 발송은 별도 인간 위임이 필요하다.
