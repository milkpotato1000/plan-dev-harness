# 사용자 결과 검토·결정 기록

Dev 원본은 docs/feedback/dev/reviews/<key>.md, plan 원장은
 docs/planning/reviews/user-reviews/<key>.md에 역할별로 작성한다.

- 공통 request key와 기존 연결 request/event:
- P/criterion 및 확인 종류·범위(UI/내용/정책 등):
- 검토 artifact 경로/URL, 정확 commit과 실질 version/hash:
- Dev 실제 결과·검증/실패/미확인·필요한 판단:
- 기존 인간 답변의 식별 가능한 출처와 그 대상/범위:
- Plan이 실제 연 파일/도구·version/hash와 관찰한 범위/한계:
- 원장 상태(접수/검토/질문대기/결정/반영) 및 기존 질문 참조:
- 실제 필요한 사용자 질문(기존 동일 범위 대기/답변이면 재발행하지 않음):
- 실제 사용자 답변·plan 판단 근거·미확정/재검토 조건:
- 결정 commit/검토 및 dev exact adoption 증거:
- 대기/차단 범위·독립 작업·사용자 중지 경계:
- 실제 전달 시도/결과/SENT·나중 관찰 ACK 근거:

상태명은 이 기록의 설명용이며 기존 runtime schema를 바꾸지 않는다. 관찰하지 않은 승인/채택을
채우지 않는다. Dev는 plan 소유 원장을 수정하지 않는다. 원문·답변·실패는 보존하고 후속 기록을
연결한다. UI 확인을 내용 승인으로 확대하거나 바뀐 결과에 옛 승인을 자동 적용하지 않는다.
Plan만 사용자 확인을 묻고, 실제 인간에게 필요한 판단만 묻는다. 링크 제공/내용 읽기와 실제
시각 검토를 구별한다. 질문·SENT·ACK·결정·채택·완료는 각각 실제 증거로만 기록한다.
