## 범위와 계약

### 입력 처리 `summarize_jsonl(text)` → dict

- 입력은 이미 디코딩된 문자열. `str.splitlines()` 기준 물리 줄에 1부터 번호를 매긴다.
  마지막 개행 유무는 결과에 영향이 없다.
- 공백만 있는(strip 후 빈) 줄은 record도 오류도 아니며 건너뛴다. 줄 번호는 계속 증가한다.
- nonblank 줄은 JSON object여야 하며 다음을 검사한다. 오류는 첫 위반 하나만 기록하고 다음 줄을 계속 처리한다.
  - JSON 파싱 실패 → `invalid_json`
  - object가 아님 → `not_object`
  - `group` 키 없음 또는 문자열 아님 → `invalid_group`
  - `lines` 키 없음, 배열 아님, 문자열이 아닌 원소 포함 → `invalid_lines`
  - 추가 키는 무시한다.
- 올바른 record는 `summarize_lines(lines)`로 (줄 수, separator 제외 문자 수)를 구한다.
  group별로 records(+1), lines, characters를 누적한다. 같은 group이 여러 번 나오면 합산한다.
- group 이름은 그대로 사용한다(빈 문자열 `""`도 유효한 group). `lines`가 `[]`이거나 모두 공백이면 records 1, lines 0, characters 0으로 집계한다.
- 반환 형태:
  `{"groups": [{"group": g, "records": r, "lines": n, "characters": c}, ...], "errors": [{"line": k, "code": code}, ...]}`
  groups는 group 이름의 파이썬 문자열 정렬순, errors는 줄 번호순. 빈 입력은 `{"groups": [], "errors": []}`.

### CLI `python3 fixture_batch.py INPUT`

- INPUT 파일을 UTF-8로 읽는다. 결과를 `json.dumps(result, ensure_ascii=False)` + 개행으로 stdout에 쓴다.
- 종료 코드: 성공(오류 0건) 0, record 오류 1건 이상 2(결과 JSON은 그대로 출력), 파일 열기/읽기 실패(OSError) 또는 UTF-8 디코딩 실패 1(stdout 없음, stderr에 짧은 메시지).
- 인자 누락 등 사용법 오류는 argparse 기본 동작(exit 2, stderr)을 따른다. 이 경우만 record 오류와 같은 코드임을 테스트에 명시한다.
- `main(argv)`를 노출해 subprocess 없이도 테스트 가능하게 한다. CLI 실제 subprocess 검증 1건 이상 포함.

### 제외

CSV 출력(P904), stdin 입력, 재접속·자동 등록·release, 반복 연산·sleep·benchmark, 재사용 배포본(harness)에 배치 기능 추가.

## 검증 계획

독립 기대값 예:
- `""` → groups [], errors [].
- `'{"group":"b","lines":["  x ","",""]}\n{"group":"a","lines":["héllo","w o"]}\n{"group":"b","lines":["yz"]}\n'`
  → groups `[{"group":"a","records":1,"lines":2,"characters":8},{"group":"b","records":2,"lines":2,"characters":3}]`, errors [].
- `'{"group":"a","lines":[]}\n\n[1]\n{bad\n{"group":1,"lines":[]}\n{"group":"a","lines":["ok",2]}'`
  → groups `[{"group":"a","records":1,"lines":0,"characters":0}]`,
  errors `[{"line":3,"code":"not_object"},{"line":4,"code":"invalid_json"},{"line":5,"code":"invalid_group"},{"line":6,"code":"invalid_lines"}]`.
- Unicode(비ASCII 문자 수 = 코드포인트 수), 빈 group `""`, 중복 group 합산, trailing newline 유무 동일, CRLF 입력.
- CLI: 정상 파일 exit 0 + stdout JSON 일치, 오류 포함 파일 exit 2 + JSON, 없는 파일 exit 1 + stdout 비어 있음, 잘못된 UTF-8 exit 1.
- 회귀: `python3 -m unittest -v test_fixture_format test_fixture_batch` 전부 PASS(P901 10 + P902 6 포함).
증거: dev 소유 보충 디렉터리 `docs/verification/P009-supplemental/`에 채택 SHA, 실제 시작/완료·checkpoint 시각, 커밋된 테스트 출력. 기존 P009-live 기록은 수정하지 않는다.
