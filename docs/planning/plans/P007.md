## 목적

사용자는 plan에서 결과물을 열어 검토하고 후속 기획·결정을 진행한다. Dev는 승인된 범위의
구현·검증을 자율 진행하며 같은 사용자 확인을 plan과 중복 요청하지 않는다.

## 기획 준비

[사용자 검토·결정 인계 계약](../P007-plan-review-gateway.md), 준비 검토와 dev 인계를 따른다.
P006의 비동기 인계를 유지하며 선행 구현/검증을 마친 안전한 경계 뒤 P007을 채택한다.

## 범위와 계약

확인·결정 요청을 dev 증거→plan 검토/필요한 사용자 질문1회→plan 결정 commit→dev 정확 채택으로
연결한다. 검토 대상·버전/hash·질문 범위별 공통 request key와 영속 기록으로 중복을 막는다.
Plan은 파일/시각 결과를 도구로 실제 열어 확인 가능한 범위를 먼저 검사하고 사용자 판단만 묻는다.
기존 합의로 결정 가능한 사항은 plan이 확정한다. 승인/권한을 새로 발명하지 않는다.
배포·설치형0.2.3 및 활성 Codex 사본에 반영하고 기존 작업·P002 중지·main을 보존한다.

## 검증 계획

상세 M1~M12: dev 무질문 인계, plan 단일 질문과 기존 답변 재사용, artifact 변경/확인 범위 차이,
결정 채택, 일반 검토와 critical OPEN 구분, busy plan/dev·중지·전송 실패·권한/host 부재,
패키지/새 세션·중복 event/semantic key·전체 회귀 및 실제 검토 능력의 한계.
