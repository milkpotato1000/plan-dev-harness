# P006 — 비동기 인계로 plan과 dev의 병렬 진행 복원

> 준비: 준비 완료
> 실행: 완료
> 우선순위: 50
> 선행: 없음
> 승인 근거: 2026-11-05 사용자 비동기 병렬 진행·P 기획/직접 dev 인계·설치형 반영 요청 및 docs/planning/reviews/P006-readiness.md

## 목적

Plan이 준비된 P를 전달한 뒤 dev 완료를 기다리며 채팅을 점유하지 않고,
사용자와 다음 요구·설계·P를 논의할 수 있게 한다. Dev는 기존 P를 보존하며 승인된 큐를 실행한다.

## 기획 준비

[병렬 진행 계약](../P006-asynchronous-handoff.md), [준비 검토](../reviews/P006-readiness.md),
[인계](../reviews/P006-dev-handoff.md)를 따른다. P005는 dev에서5/5 완료했으며 P002는2/5 중지 유지다.

## 범위와 계약

설치형 source/assets/스킬·references/prompts/bootstrap 진입점의 비동기 인계 규칙을 patch0.2.2로
일치시킨다. 현재 실제 로드된 Codex 설치 사본도 백업·확장 보존·검증 후 갱신한다.
Plan은 commit→전달→실제 SENT 기록·commit/push 후 응답을 종료한다. ACK/채택/완료 대기를
인계 성공 조건으로 삼지 않는다. Dev는 실행 중인 P를 임의 중단하지 않고 안전한 경계에서
전달된 정확 검토 SHA를 채택하며, 준비·우선순위·의존성·중지/결정 조건을 지켜 진행한다.
기존 기록·실행 로그·실패·사용자 중지를 보존한다. 상세 예외와 검증은 계약을 따른다.

## 검증 계획

독립 N1~N10 기대 행동, 전송 성공/실패/불명·ACK 미관찰·busy dev·추가 P의 정확 채택·역할별
중지/legacy all 중지·OPEN 결정·설치형 양 host/upgrade/bootstrap 회귀, 전체 테스트·guard/큐.
실제 호스트 송신과 모델 행동 검토·시뮬레이션·기계 테스트는 구분하여 증거를 남긴다.
