# P003 — 명시 승인된 직접 인계 절차와 배포 정합성 개선

> 준비: 준비 완료
> 실행: 진행 중
> 우선순위: 20
> 선행: 없음
> 승인 근거: 2026-10-29 사용자 추가 계획 작업 진행 요청 및 docs/planning/reviews/P003-readiness.md의 범위·계약 준비 검토

## 목적

사용자가 직접 전달을 명시 지시했거나 범위가 일치하는 기존 인간 위임이 확인될 때,
에이전트가 수신자·커밋·다음 행동을 확인하고 실제 전달·수신 근거까지 기록하게 한다.
소스·배포 assets·프로젝트 설치·개인 스킬의 차이로 그 절차가 누락되는 문제도 다룬다.

## 기획 준비

- [요청 접수·중복 검토](../reviews/P003-request-review.md) 및
  [확정 계약](../P003-direct-handoff.md)과 [준비 검토](../reviews/P003-readiness.md)를 근거로 한다.
- 상태 머신은 P001에 이미 존재한다. P002는 실제 인계 검증이다. 이번 카드는 일상 전달 절차와
  배포/업그레이드 안내 개선이며 P002를 대체하거나 수정하지 않는다.
- P002와 의미상 연계되나 구현 선행은 아니다. 기존 승인된 P002를 이 카드 때문에 막지 않는다.
- 사용자 추가 진행 요청으로 기존 접수의 검토 한정을 넘어 이 제품 개선 범위의 계획을 확정했다.
  plan 소유 docs/process 네 문서를 개정하고 manifest 관리 대상 세 문서의 hash를 갱신·검토했다.
  dev는 준비 검토를 포함한 정확한 plan 커밋을 통합·채택한 뒤 배포 소스·테스트를 구현한다.
- 실제 발송/개인 설치 전환 권한은 카드 준비와 별개다. 기존 상시 위임을 임의로 만들지 않는다.

## 범위와 계약

1. 권한·대상 역할 채팅·프로젝트·commit/P카드·다음 행동을 확인하는 직접 발송 절차를
   skill/reference/배포 지침에 연결한다. 인간 위임의 출처·범위·대상을 기록한다.
2. 명시 승인 및 도구가 있으면 에이전트가 직접 발송하고 실제 성공으로 SENT를 기록한다.
   read/wait 등으로 실제 수신 응답을 확인해 ACK를 기록한다. 전송과 수신, 채택과 완료는 구분한다.
3. 권한 없음/도구 없음/대상 불명/중지/결과 불명에 대한 파일 인계와 보류 처리를 정의한다.
   가능 여부 질문·다른 에이전트의 전달 요청·초기 채팅 생성 권한으로 발송을 확대하지 않는다.
4. ACK 재전송과 연쇄 전달을 금지하고 메시지 수신만으로 새 실행 권한이나 재개가 생기지 않게 한다.
   기존 제어 CLI와 읽기 전용 큐, exact adoption, 중지 및 원본 기록 보존을 유지한다.
5. 소스→assets→프로젝트 설치와 소스→개인 스킬의 서로 다른 배포 경로를 문서화하고 검증한다.
   같은 이름의 구형 스킬과 로드 경로를 확인하며 기존 파일·사용자 확장·훅을 덮지 않는다.
6. 구현 범위는 문서 기반 호스트 어댑터와 배포/충돌 검증이다. 자동 메시지 서비스,
   새로운 런타임 상태 머신·플러그인 로더·강제 업그레이드 플래그는 포함하지 않는다.
   실제 개인 설치/다른 프로젝트/전역 설정/main·릴리스 변경은 이 카드 범위에 포함하지 않는다.

## 검증 계획

- 확정 계약의 M1~M8에 따라 명시 지시, 범위 한정 기존 위임, 단순 질문, 에이전트 수신,
  도구 부재, 대상 불명, 실패/결과 불명, 중지, 단순 ACK와 중복을 독립 기대값으로 검토한다.
- stub/기록 기반 절차 검증과 실제 호스트 메시징 검증은 따로 보고한다.
  별도 실제 사용자 발송 권한이 없으면 실제 발송 성공을 주장하지 않는다.
- 임시 목적지에 Codex/Claude 스킬을 preview/apply하여 독립 payload·링크·CLI를 검사한다.
  임시 프로젝트 업그레이드와 충돌 보존, 기존 개인 설치와 같은 legacy 구조 보존을 검사한다.
- 소스/배포/설치본의 version·commit·hash·로드 경로와 구형 기능의 보존/변경 대조표를 남긴다.
  의미 없는 문구 일치 테스트로 절차 적합성을 대신하지 않는다.
- 관련 구현 변경 후 dev의 전체 회귀와 guard/queue 검사를 수행하고
  `docs/verification/P003/`에 실제 결과·한계·실패 및 재검증 증거를 커밋한다.
