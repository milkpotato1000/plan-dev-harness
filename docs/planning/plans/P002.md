# P002 — 실제 세션 간 결정 대기·중지·인계 흐름 검증

> 준비: 준비 완료
> 실행: 차단
> 우선순위: 10
> 선행: 없음
> 승인 근거: 2026-10-29 사용자 요청(P002 기획·준비 검토·dev 큐 등록) 및 docs/planning/reviews/P002-readiness.md의 준비 검토

## 목적

두 실제 역할 채팅이 같은 Git 계약을 읽고 결정 대기, 사용자 중지, 명시적 재개,
증거 기반 인계를 이어가는지 확인한다. 기존 CLI 회귀와 채팅 초기화 확인을 넘어,
어느 세션이 어떤 커밋을 보고 판단·행동했는지 재검토 가능한 근거를 남긴다.

## 기획 준비

- P001은 dev에서 구현·검증 완료된 역사적 계약이다. parsed 선행 카드로 연결하거나
  다시 실행하지 않는다. 기존 기능·검증과 로컬 설치 완료를 전제로 검증 준비를 시작한다.
- 기존 근거: dev `8bd941471db02ccb641e26835e7edcfd5a84ad28`의
  `docs/verification-v0.2.0.md`, dev `d2b900713fb8aa7be8f1599c9ef92e5b401339dc`의
  `docs/verification-local-harness-setup.md`, [로컬 설치 검토](../reviews/local-harness-setup.md).
- 상세 절차·독립 기대값·중단 및 재개 조건은
  [P002 검증 계약](../P002-session-validation.md)을 따른다.
- 준비 검토 결과: 요구·범위·역할·검증·증거·완료 조건 확정. dev는 이 카드와 검토가
  포함된 정확한 plan 커밋을 통합·채택하고 준비부터 착수한다.
- 실제 양쪽 채팅 참여와 단계별 사용자 중지·재개 발언은 실행 단계의 입력이다.
  준비 가능 상태와 실제 세션 검증 완료를 구별한다. 입력이 없으면 해당 단계에서
  이유·필요한 입력·재개 지점을 남기고 기다리며 대체 PASS를 만들지 않는다.

## 범위와 계약

1. 현재 배포 저장소의 dev에서 증거를 관리하되, 제어 흐름은 별도의 로컬 검증 저장소와
   plan/dev worktree에서 재현한다. 실제 두 역할 채팅이 각자 역할의 검증 worktree만 쓴다.
   같은 채팅이 양쪽 역할을 실행한 결과나 subprocess 두 개는 실제 세션 검증을 대신하지 못한다.
2. 검증 저장소는 부재한 임시 경로에 preview 후 생성한다. 비민감 fixture만 사용하고,
   원격을 만들지 않는다. 배포 저장소의 실제 큐에는 가상 결정·중지·시험 카드를 넣지 않는다.
3. 미분류 결정의 전체 차단, plan의 범위 분류와 dev 채택 전후 차이, 관련·의존 작업 차단과
   무관 작업 진행, 전체 SHA 채택 후 해결, 해결과 사용자 중지의 독립성을 확인한다.
4. 역할 한정 중지와 전체 중지, 상대 미커밋/커밋 상태의 가시성, 양쪽 독립 중지와
   한쪽 재개, 실제 사용자 발언을 근거로 한 명시적 재개를 확인한다.
5. 인계의 PENDING 생성·중복 방지·SENT·ACKNOWLEDGED를 실제 전달과 수신 확인에 연결한다.
   이번 큐 등록은 채팅 발송 권한이 아니다. 사용자의 수동 전달 경로를 기본으로 하며,
   도구 발송은 사용자가 대상과 발송을 명시적으로 허용한 경우만 사용한다.
6. 공개 가능한 증거는 `docs/verification/P002/`에 기록한다. 세션별 발언·행동·시각·커밋,
   queue JSON, CLI stdout/stderr/exit code, 원본 제어 기록과 Git 이력을 연결한다.
   실패와 보류를 보존하고 실행하지 않은 시나리오를 PASS로 표시하지 않는다.
7. P002는 검증 작업이다. 제품 동작·정책·설치 runtime·배포 assets·개인 스킬·다른 프로젝트,
   실제 main·태그·릴리스·공유 훅 설정 변경은 범위 밖이다. 발견된 결함/새 요구는
   기존 intake 절차로 기록하고 plan 검토로 넘긴다. 필수 실패를 숨긴 채 P002를 완료하지 않는다.

## 검증 계획

- 대상: 현재 macOS의 실제 Codex plan/dev 역할 채팅 2개, Git/Python CLI와 커밋된 runtime.
  사용한 앱·모델·Python·Git·소스 및 채택 SHA를 기록한다. Claude Code·다른 OS 검증으로 확장하지 않는다.
- S0~S5를 검증 계약 순서로 수행한다. 기대값은 실행 전에 계약에 고정한다.
  코드가 출력한 값을 그대로 기대값으로 채택하지 않는다.
- 사용자 중지 이후에는 업무 선택을 멈추고 checkpoint·증거 보존 및 사용자가 요청한
  상태 확인만 한다. 재개 명령은 중지 이후 새로 도착한 실제 사용자 요청에만 따른다.
- 기존 CLI 자동 회귀는 보조 증거다. dev에서 `python3 -m unittest discover -s tests -v`를
  수행하고 결과를 보존한다. 실제 세션 수행 결과와 별도로 보고한다.
- 복구는 보존된 checkpoint/커밋에서 진행한다. 실패 이력, 질문 원문, 인계 이력은 지우지 않는다.
  검증 저장소는 증거가 dev에 커밋되기 전 정리하지 않는다.
