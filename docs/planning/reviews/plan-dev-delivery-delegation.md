# 이 프로젝트 plan → dev 직접 전달 위임 — 2026-10-29

인간 요청 원문: “plan이 자동으로 dev 로 계획 넘겨서 시작하게 해줘.”

이 plan 채팅에서 실제 사용자가 부여한 프로젝트 한정 전달·착수 위임을 기록한다.
앞선 P003의 일반 절차는 위임 자체가 아니었으며, 이 요청이 이 저장소의 실제 근거다.

- 대상: 이 저장소와 같은 저장된 컨테이너 프로젝트의 검증된 기존 dev 역할 채팅.
  매번 목록/읽기로 현재 프로젝트·역할·worktree를 확인한다. 공개 문서에는 실제 채팅 ID를 넣지 않는다.
- 동작: 승인된 프로젝트 목표 안에서 plan이 계약·준비 검토를 완료해 READY로 커밋한 계획을
  전체 SHA·문서·범위·검증·상한·다음 행동과 함께 직접 전달하고 dev 착수를 요청한다.
  이 범위의 인계에 재결재나 사용자의 복사 전달을 요구하지 않는다.
- dev 착수: 기존 변경과 실패 기록을 보존하며 정확한 계획 커밋을 통합·채택·커밋하고
  guard/큐를 확인한 뒤 준비된 작업을 진행한다. 요구·완료 조건을 dev가 재해석하지 않는다.
- 발동: 이 plan 채팅이 준비 완료를 처리하는 작업에서 직접 수행한다. 읽기 전용 큐 명령이나
  Git 훅이 자체적으로 발송한다고 주장하지 않는다. 별도 스케줄러나 새 채팅을 만들지 않는다.
- 상태: PENDING 생성 후 실제 전송 결과로 SENT, read/wait로 관찰한 실제 수신 응답으로 ACK를
  기록한다. ACK는 채택/구현 완료와 구별한다. 같은 이벤트/단순 ACK에 재전송하지 않는다.
- 범위 밖: 초안, 승인되지 않은 새 요구, 다른 프로젝트/대상으로의 발송, 역방향/연쇄 발송,
  main·태그·릴리스·개인 설치 변경, 실제 사용자 중지/결정 대기/필수 검증의 우회.
- 유지/철회: 이후 실제 사용자의 제한·중지·철회가 우선한다. 도구/수신자가 확인되지 않으면
  근거와 커밋된 파일 인계를 남긴다. 불명 결과는 수신 상태부터 확인하며 중복 발송하지 않는다.

현재 첫 적용 범위는 [P002/P003 인계](P002-P003-dev-handoff.md)다.
수신자가 해당 계획을 읽었다는 응답·도구 결과는 별도 전달 근거에 보존한다.
이 문서는 실제 전송 성공이나 수신·구현 완료가 있었다고 미리 기록하지 않는다.
