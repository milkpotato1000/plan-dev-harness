## 필요한 실제 입력과 중복 방지

원래 `docs/planning/P002-session-validation.md` S3.6:
“사용자가 dev 역할만 중지를 요청하면 dev가 role pause를 기록·커밋한다.”
기존 현재 재개 요청은 이 미래 새 중지를 대신하지 않는다. Plan은2026-11-05
request_user_input_async로 아래 한 질문을 실제 발행했고 도구 accepted=true를 받았다.

> P002의 남은 S3.6 검증을 위해 시험용 dev 역할만 다시 중지할까요? 중지 후 결정만
> 해결해도 작업은 계속 멈춰 있는지 확인하는 시험입니다. 기존 P002 검증 계약이 실제
> 사용자 중지 발언을 요구하며, 다른 프로젝트에는 영향이 없습니다.

선택지: “P002 시험의 dev 역할만 지금 중지해줘.” / “새 중지 시험은 진행하지 마.”
아직 답변이나 새 PAUSED를 관찰하지 않았다. 기본 선택·시간 경과·에이전트 메시지는 실제
답변이 아니다. 같은 key의 후속 전달은 이 대기 질문을 참조하고 dev/plan이 다시 묻지 않는다.
답변은 원문/관찰 시점/범위를 덧붙여 기록한다. 실제 pause 후에 별도 resolve-only 요청,
그 후 S3.7 재개 요청을 해당 단계에서만 받는다. 선제 승인·가상 인간 발언을 만들지 않는다.

## 다음 실제 dev 행동

Dev는 위 fixture plan resume commit/자기 queue를 독립 관찰하고 증거를 보존한다.
원본 현재 재개를 다시 묻거나 plan에게 ACK 회신만 보내지 않는다. 새 중지 입력이 오기 전에는
pause/resolve/P901/P903 실행을 하지 않는다. 이 계획은 전달 후 응답을 끝내며 완료 감시를
하지 않는다. 필요한 실제 인간 입력은 plan 창구의 이 원장으로 연결한다. S4/S5는 미완료다.

## 실제 인간 답변 수신 — 2026-11-05

위 단일 질문에 연결된 실제 사용자 답변을 이 plan 채팅에서 수신했다.

> P002 시험의 dev 역할만 지금 중지해줘.

상태: 답변 수신·범위 확정, dev 실제 pause 실행은 아직 미관찰. 원래 질문과 답변의
연결은 host의 send_user_message_question_reply로 확인했다. 앞의 답변 대기 기록은
발행 당시 이력으로 보존한다. 같은 중지 의사를 다시 묻지 않는다.

승인 범위는 P002-20261029-A-CONT-20261105의 fixture dev 역할만이다. 실제 dev writer가
자기 checkpoint에 `pause --scope role`을 이 실제 인간 답변을 참조해 기록·커밋한다.
Plan 역할과 다른 프로젝트·배포 저장소 작업 전체를 중지하는 요청이 아니다. 현재 S3.6의
결정 해결이나 미래 S3.7 재개를 함께 승인한 답변도 아니다. 두 번째 질문은 OPEN으로 보존한다.

다음 실제 dev 행동: 기존 actual plan resume를 관찰한 현재 상태를 보존하고, 이 STOP 지시를
우선 처리한다. 이미 동일 답변으로 중지됐다면 이력을 중복 추가하지 않고 실제 근거를 연결한다.
원래 체크포인트 이력을 보존하고, plan ACTIVE/dev PAUSED(role), next.plan=P904/next.dev=null,
두 번째 OPEN 원문/hash 유지, P901/P903 미실행과 guard를 검증한다. 실제 pause commit과
그 근거를 plan에 전달해 다음 별도 resolution-only 입력을 plan에서 한 번 받을 수 있게 한다.
현재 중지 입력·기록이 없는 상태에서 미래 질문이나 resolve를 미리 처리하지 않는다.

Plan은 커밋된 답변과 정확 SHA를 확인된 기존 dev에 직접 전달하고 실제 SENT만 기록한다.
이 요청은 중지/검증 다음 행동이며 단순 ACK ping이 아니다. 배포 계약 채택이 필요한 경우에도
중지 요청을 무시한 채 새 fixture 업무를 먼저 실행하지 않는다. 실제 인간 원문은 이 plan
채팅의 답변에서 확인 가능하며, 전달 에이전트 메시지를 인간 원문으로 꾸미지 않는다.
