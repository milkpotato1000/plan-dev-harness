# P003 설치형 직접 인계 규칙 반영 검토 — 2026-10-29

사용자 요청: “이 룰은 플러그인 설치형 자체에 반영 해놔줘.”

판정: 기존 P003의 소스·배포 정합성 범위에 포함한다. 이 저장소의 실제 plan→dev 위임을
기록한 AGENTS만 바꾸는 것으로 완료하지 않는다. 독립 복사·설치된 스킬과 생성된 프로젝트의
규칙·역할 프롬프트에도 인간 위임에 따른 직접 전달·착수 절차가 있어야 한다.

## 배포할 규칙

인간이 해당 프로젝트의 plan→dev 전달·착수를 명시 위임했고 호스트 도구/기존 대상이
확인되면, plan은 승인된 목표의 준비 완료 계획을 커밋하고 정확한 SHA·인계 문서를 dev에
직접 보낸다. 동일 범위의 재결재나 사용자 복사 전달을 기본 경로로 삼지 않는다.
dev는 기존 작업·실패 로그를 보존해 정확한 계획을 통합·채택한 뒤 큐를 시작한다.
SENT/ACK/채택/완료를 구별하고 중지·미해결 결정·역할을 보존한다.

이것은 설치형의 공통 행동 규칙이다. 설치만으로 대상 프로젝트의 발송 권한이 생기는 것은
아니다. 실제 위임은 프로젝트의 인간 요청에서 확인·보존하며 대상/범위를 재검증한다.
이 프로젝트의 사용자 인용·채팅 ID·실제 위임 기록을 다른 프로젝트에 심지 않는다.
권한/도구/대상이 없으면 기존 파일 인계를 사용하고 거짓 SENT/ACK를 만들지 않는다.
채팅 bootstrap의 읽기 전용 확인·대기와, 그 이후 위임받은 READY 인계·착수를 구분한다.

패키지 반영 결과와 기존 개인 설치의 자동 동기화를 같은 것으로 보고하지 않는다.

## dev 인수와 완료 근거

P003의 체크 문구와 실행 로그 소유권은 그대로 둔다. dev는 진행 중인 변경을 보존하며
이 문서·갱신된 P003 계약이 포함된 정확한 plan snapshot을 안전한 시점에 통합·재채택한다.
직접 인계 위임에 따라 이번 구체화도 같은 프로젝트의 dev에 전달한다.
dev의 실제 구현 커밋과 독립 설치·생성 출력의 검증 근거를 읽어 설치형 반영을 확인한다.
기획 변경이나 전달 성공만으로 패키지 반영이 완료됐다고 쓰지 않는다.
