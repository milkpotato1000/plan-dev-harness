# 이 프로젝트 dev→plan 결과 검토·결정 인계 위임 — 2026-11-05

실제 인간 지시: ‘dev 작업 -> 확인 요청은 플랜으로 전달 해서 플랜에서 파일등을 띄우고 확인하고
(이 과정이 작업 결과를 살펴보며 추가 플래닝 하는 과정임) 하도록 하자. … 결정사항 발생 ->
플랜으로 인계 -> 플랜에서 결정.’

범위: 이 하네스 저장소에서 확인된 기존 dev와 기존 plan 사이의 커밋된 결과검토/필요한 판단
인계, 그리고 기존 plan→dev 위임에 따른 검토된 결정/작업 전달. 현재 사용자 지시는 실제
인간 근거이며 수신 에이전트 메시지를 권한으로 삼는 것이 아니다.

Dev는 P/검증/실패·artifact version/hash·공통 request key·질문 범위·기존 사용자 답변 출처·
다음 행동을 커밋하고 기존 plan을 확인해 전달한다. Plan은 실제 결과를 검토하고 공통 원장으로
중복 질문을 막는다. 기존 합의 내 판단은 확정하고 실제 인간 판단은 plan에서 한 번 묻는다.
결정은 commit 후 dev exact adoption으로 전달한다. P007 계약과 실제 pauses/OPEN이 우선한다.

위임 밖: ACK/무관한 상태 ping·자동 완료 감시·다른 프로젝트/수신자·새 채팅·무한 연쇄·
서비스 쓰기·새 업무 승인·권한 우회·사용자 중지 재개. 설치 자체는 다른 프로젝트의 위임이 아니다.
실제 도구 성공만 SENT, 수신 근거만 ACK. 대기 loop 없이 응답 종료, 불명/실패는 근거 보존.
확인한 상대가 없으면 durable pending 문서만 남기며 발송 성공을 꾸미지 않는다.
