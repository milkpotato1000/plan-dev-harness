# P001 — v0.2.0 결정 대기·사용자 중지·인계

상태: 구현·검증 완료 (dev, main 승격 전). 사용자가 승인한 범위의 계획을 먼저 커밋한 후 구현했다.
범위: 이 배포 저장소만. 기존 사용 프로젝트, 개인 스킬, 외부 업무 도구는 변경하지 않는다.
배포: dev에서 구현·검증·공유. main 승격/릴리스는 별도 명시 요청에 따른다.

## 문제와 결과

신규 요구 접수는 작업 중지를 뜻하지 않는다. 중대한 결정이 필요한 작업은 plan 판단을
기다리고, 사용자의 중지는 그 결정 해결과 별개로 유지되어야 한다. 다음 세션은 커밋된
인계 기록으로 완료/미완료와 다음 행동을 이어받아야 한다.

## 구현 계약

1. 기존 Markdown PLAN_DECISION OPEN/RESOLVED를 읽는다. 기존 범위 없는 OPEN은 dev 전체 차단.
   새 결정도 영향 판단 전에는 전체 차단. plan 소유의 보호된 분류 기록이 요청 내용 hash,
   근거, 영향 P카드를 지정하면 해당 작업과 의존 작업만 차단한다. dev가 범위를 축소하지 못한다.
   RESOLVED는 전체 결정 SHA가 채택 plan 이력에 포함되어야 한다. 삭제로 차단을 우회하지 않는다.
2. 사용자 PAUSED/ACTIVE checkpoint를 읽는다. 기본은 양쪽 역할 중지, 명시적으로 role을
   지정하면 해당 역할만 중지한다. 재개 요청 기록 없이 ACTIVE가 되지 못한다. 중지는
   결정 해결/새 계획/시간 경과로 해제되지 않는다. Git으로 보이지 않는 상대 상태까지 보장하지 않는다.
3. CLI로 결정 요청/분류/해결, 사용자 중지/재개, 인계 생성/전달 상태 기록을 제공한다.
   CLI는 메시지 전송/모델 실행/자동 작업 시작을 하지 않는다. 권한 근거는 사람이 제공한
   요청 참조이며 실제 발언의 진위는 자동 입증하지 않는다.
4. 인계 event key(종류, 수신 역할, 근거 커밋, 문서)로 중복을 방지한다.
   PENDING → SENT → ACKNOWLEDGED는 전달/수신 증거가 있어야 기록한다. 실제 자동 전송은 없다.
5. 일반 intake 대기는 무관한 승인 작업을 막지 않는다. 큐 JSON은 기존 키를 보존하면서
   pending_decisions, paused_sessions, handoffs, task별 차단 사유를 추가한다.
6. 기존 설치 manifest를 유지해 v0.1.0→v0.2.0을 preview/upgrade할 수 있다.
   사용자 변경 파일/추가 훅/기존 지침과 기록을 덮어쓰지 않는다. 다른 브랜치명도 지원한다.
7. Asana/서비스 승인/호스트 메시징은 선택 어댑터 경계와 예제 계약만 문서화한다.
   회사 식별자나 제품 규칙을 포함하지 않으며 기존 확장을 제거하지 않는다.

## 실행 기록

계획 검토: 범위/권한/기존 호환성을 확인했다. 중지 기록은 보존·커밋을 막지 않고 큐 선택을
제어한다. Git 훅은 실행 중인 프로세스나 외부 서비스 작업을 강제로 중단하지 않는다.
